# 视频转文字工具整改方案

> 一句话：**选完文件即见参考价格并完成余额拦截（前端读时长），点击生成上传后按服务端实测的真实音频时长预扣智点，源视频用完立即删除。**
>
> v1.4 · 2026-09-01 · 待评审（本迭代内全部完成，P0/P1/P2 表示优先级）
>
> v1.4 修订：余额校验回到点击「开始生成」时（按前端估算智点判断，含 0 智点拦截，不触碰存储）；实际预扣在上传后按服务端实测音频时长计算；删除「已上传但余额不足保留 2 小时」规则（该场景已不存在）。

---

## 一、现在有什么问题

| 问题 | 后果 |
| --- | --- |
| 游客（未登录）也能上传 | 上传免费且不记名，被恶意刷量时连是谁都查不到，存储（存用户文件的云端空间，按容量和流量计费）迟早被占满 |
| 传上去的文件没人管 | 传错视频换一个，旧的永远留在存储里；传完不用的也一直占着。反复操作 = 存储被刷爆 |
| 0 智点用户也能传 | 传完 2GB 大文件后才知道要充值，用户白忙一场非常恼火，充值转化反而更低 |
| 长视频上传久、按钮灰着没解释 | 20 分钟以上的视频要传十几分钟，期间没有任何进度和说明，用户以为卡死了，流程直接断掉 |
| 传完才看到价格 | 用户对要花多少智点完全没有预期，价格只在最后一步出现 |

## 二、新流程

```
① 选择/拖入文件 → 文件只载入浏览器，不产生任何上传
② 前端读取时长 → 显示「时长 X · 预计消耗约 Y 智点」
   （前端读数可能不准：仅用于展示参考 + 生成前的余额充足性判断；
    登录用户同时显示当前余额，游客不显示余额）
③ 点击「开始生成」
   ├─ 未登录 → 弹出登录窗口，登录成功后自动继续（文件无需重选）
   ├─ 余额 < 预估智点 Y（含 0 智点）→ 弹出充值窗口，流程停止（未上传、未扣费）
   └─ 余额充足 → 分片上传到对象存储（显示进度、支持断点续传）
④ 上传完成 → 服务端读取真实音频时长 → 按真实时长计算并扣除智点 → 调转写 API 处理
⑤ 任务完成 → 展示结果（实际时长 X 分钟 · 实际消耗 Y 智点）→ 源视频立即从对象存储删除
   预扣（真实时长）与实扣（API 实际计量）的差异多退少补
⑥ 任何中断（关闭页面 / 断网 / 任务失败）→ 已传内容清理 / 智点全额退还
```

> 与现状的关键区别：**上传从「选完文件自动传」推迟到「用户明确点击开始生成」；余额不足在点击时就被拦下，根本不触碰存储；预扣与结算都以服务端/API 实测的音频时长为准；源视频用完即删。**

## 三、改动清单（同一迭代内完成）

### 1. 游客与登录【P0】

- 选完文件后，所有人都能看到「时长 + 预计消耗智点（参考）」；**当前余额仅登录后显示**。
- 游客点击「开始生成」时弹出登录窗口，登录成功后自动继续当前任务（文件无需重选）。
- **服务端必须同步校验**：未登录的上传/任务请求一律拒绝——前端弹窗只是引导，拦不住绕过页面直接调接口的恶意请求。
- 复用现有登录弹窗组件（工作区其他入口已有同款拦截）。

### 2. 前端如何读时长、算智点【P1】（实现指引）

1. **触发时机**：文件选择/拖入成功后立即执行；只持有文件引用（File 对象），不读入全部内容、不上传。
2. **第一优先：`<video>` 读元数据**。用 `URL.createObjectURL(file)` 生成临时地址，监听 `loadedmetadata` 事件，读取 `duration`（秒）。适用于 mp4 / webm / mov 等浏览器可直接解析的格式，耗时约几百毫秒。
3. **第二优先：工具库兜底**。mkv / avi / flv / wmv / mpeg 或第一步失败时，加载 mediainfo.js（浏览器端解析音视频文件信息的工具库，约 2~3MB，建议页面空闲时提前加载好）读取文件头中的时长；只读取文件头尾少量字节（`File.slice` 切片读取），2GB 文件内存占用也很小。
4. **仍失败或超过 3 秒**：显示「未能识别时长，费用以上传后确认为准」，不阻塞用户继续。
5. **预估智点计算**：费率（智点/分钟）由服务端配置接口下发（调价不用发版）；`预估智点 = 向上取整(时长秒 ÷ 60) × 费率`，不足 1 分钟按 1 分钟算。前端读数可能不准，因此**向上取整、宁可多估不少估**。该估算有两个用途：①展示参考（文案带「预计」字样）②点击生成时的余额充足性判断。mpeg 格式额外标注「以上传后确认为准」（这种格式读出的时长是估算值）。
6. **合理性校验**：时长 ≤ 0 按「读不到」处理；时长 > 12 小时或文件 > 2GB 或格式不支持 → 当场拒绝并说明原因，不上传。
7. **边界说明**：前端读数只用于展示和生成前的余额判断；**实际预扣与结算一律以服务端/API 实测的音频时长为准，差异多退少补**。

### 3. 扣费与上传时序【P0】

- 「开始生成」后的顺序固定为：**登录校验 → 余额校验 → 上传 → 服务端读真实音频时长 → 按真实时长预扣智点 → 调 API**，顺序不可颠倒。
- **余额校验在点击时进行**，依据 = 前端估算智点（含 0 智点）；不足则弹充值窗并展示缺口（「预计需 X 智点，当前余额 Y」），**不扣费、不上传、不触碰存储**。
- **预扣依据 = 服务端实测的音频时长**，不使用前端读数。若真实预扣高于前端估算、导致余额不足以扣除（估算低估的情况，如 mpeg 文件），处理方式见「需要拍板」第 1 条。

### 4. 源视频与存储清理【P0】

- **任务完成 → 源视频立即从对象存储删除**，不保留。
- **生成结果的历史记录保留 3 天**，到期自动清理（沿用现有文案口径）。
- 上传中断（关闭页面、更换/取消）→ 立即中止并清理已传分片；断网等异常 → 超时 1 小时兜底清理。
- 对象存储上保留「到期强制删除」开关（24 小时兜底）——即使程序漏删，成本也有硬上限。
- **不设单日上传上限**：存储只在用户点击开始生成且余额充足后被触碰、任务完成即删，单人瞬时占用上限 = 5 个并发任务 × 2GB = 10GB，有界可控。

### 5. 上传体验【P1】

- **分片上传 + 断点续传**（大文件切成小块传，网断了从断点继续，不用从头重来）——长视频上传成功率的最大变量。
- 按钮状态：「上传中 65% · 预计还需 2 分钟」→「正在生成」→ 完成；任何不可点击状态必须说明原因。
- 大文件选完即提示预期：「该视频较大，预计上传 X 分钟」。

### 6. 计费与结算【P0】

- **计费口径：音频时长**。余额拦截按前端估算智点；预扣按服务端实测音频时长；结算以转写 API 实际计量为准，多退少补。
- 结果页展示「实际时长 X 分钟 · 实际消耗 Y 智点」，让用户清楚钱花在哪。
- 任务失败或超时 → **自动全额退还预扣智点**，并明确告知用户。
- **并发任务上限：每人同时 5 个**，第 6 个拒绝并提示「有 5 个任务进行中，请等待完成」。

## 四、验收标准（全部通过才算完成）

| # | 验收项 | 通过标准 |
| --- | --- | --- |
| 1 | 游客选完文件 | 可见「时长 + 预计智点（参考）」，不可见余额 |

| 4 | 选完文件（常规格式） | 3 秒内显示时长与预估智点；预估文案带「预计」标识；mpeg 旁有「以上传后确认为准」标注 |
| 5 | 时长读取失败 | 显示「以上传后确认为准」，仍可继续点击生成 |

| 7 | 点击「开始生成」，余额 < 预估智点（含 0 智点） | 弹充值窗并展示缺口；不扣费、不上传、存储无文件 |
| 8 | 余额充足 | 直接开始上传；上传完成前不产生任何扣费 |
| 9 | 上传完成 | 服务端读取真实音频时长，按真实时长计算并扣除智点（不使用前端读数） |
| 10 | 扣费后 | 调转写 API；结果页显示实际时长与实扣智点，多退少补到账 |
| 11 | 任务完成 | 源视频立即从存储删除（存储侧可验证不存在）；结果记录保留 3 天 |
| 12 | 任务失败 / 超时 | 预扣智点自动全额退还 |
| 13 | 已有 5 个进行中任务 | 第 6 个被拒绝并提示 |
| 14 | 上传中断网 | 恢复后从断点续传；上传中显示百分比与预计剩余时间 |
| 15 | 上传中关闭页面 | 已传分片被服务端清理，存储无残留 |
| 16 | 计费全链路 | 余额拦截按前端估算；预扣与结算按服务端/API 实测音频时长 |

## 六、上线后看这几个数

- **孤儿文件率**（任务完成后未删除、白占空间的文件占比）→ 目标趋近 0；
- 「开始生成时因余额不足被拦截」用户的充值转化率 → 提升；
- 长视频上传完成率 → 提升；
- 游客被登录拦截后完成登录并继续上传的比例 → 建立基线后优化。

## 七、需要拍板的事

1. **真实预扣 > 前端估算且余额不足差额**（估算低估的情况，如 mpeg 文件；此时文件已传、任务待跑）：建议允许余额临时为负、下次充值优先抵扣，否则只能扣到 0。需要定。
2. **0 智点小样策略**：允许免费转 1 分钟以内的小视频（先体验价值再引导充值），做不做。
3. **文案说明**：结果页需向用户说明「源文件已删除，文字结果保留 3 天」「预估仅供参考，以实际上传后确认为准」，避免误解。
